Verify-While-Writing

Attribution-first decoding for clinical summarization

+
STACK
Python, OpenAI API, NLI scoring, MC-dropout
RESULT
0.255 → 0.141 hallucination rate
SIGNIFICANCE
Wilcoxon p = 0.00033, d = 0.806
CITATION COVERAGE
0% → 100%

The model generates the Brief Hospital Course one chunk at a time, citing EMR sources inline as it writes; each statement clears an automated verification layer — entity checks, lab rules, NLI scoring, MC-dropout uncertainty — before it is committed. On 30 synthetic Synthea cases with gpt-4o-mini, that cuts the hallucination rate 44.8%. Verifying after generation instead showed no significant improvement (p = 0.31), which is the finding: grounding has to happen while the model is writing. Conducted through Algoverse AI Research.

OPEN PR

vLLM, FlashInfer sampler fallback

Crash-on-startup bugfix in the sampling engine

+
STACK
Python, PyTorch, vLLM internals
STATE
Open, awaiting review and rebase

FlashInfer JIT-compiles its top-k/top-p sampling kernels on first use. When that build failed, the exception took down engine startup with no fallback. This patch wraps both sampler call sites, in the V1 and V2 model runners, so a build failure degrades once to the native PyTorch sampler instead of crashing; explicit opt-in via the env flag still raises a clear error naming the responsible flag. Two regression tests added, verified end-to-end on a machine with no discoverable CUDA toolkit.

Header-only pool with future-based result handoff

A header-only pool built on a std::mutex / std::condition_variable task queue with std::future result handoff. Tasks are type-erased and queued; exceptions thrown inside a task propagate correctly through future::get(). Submission is re-entrant, so a task running on the pool can submit and await further tasks. Two different speedup figures exist across earlier drafts, so this card holds at verifying until one clean benchmark run settles the number.
