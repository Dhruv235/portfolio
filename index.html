vLLM: FlashInfer sampler fallback

vllm-project/vllm #51741 ↗fixes issue #49497 ↗
PROBLEM

FlashInfer JIT-compiles its top-k/top-p sampling kernels on first use. If that build fails at call time, the exception crashes engine startup with no fallback.

FIX

Wrapped the FlashInfer sampling call in both model runner paths (V1 and V2) so a build failure warns once and permanently falls back to the PyTorch-native sampler. If the user explicitly forced FlashInfer with VLLM_USE_FLASHINFER_SAMPLER=1, it raises a clear error instead of silently falling back.

VALIDATION

2 regression tests. The same 34 pre-existing failures occur with and without the change, so there are no regressions. Two other contributors independently verified it: one on a GB10 confirmed byte-identical sampling output on the success path, and one on an RTX 3090 confirmed the crash is fixed on the v0.30.0 release (with the change ported onto that release).

SCOPE

The PR includes a table separating three failure modes in this area and explains why it handles only the third: a build that fails after FlashInfer is already selected, which no selection gate can predict.

Throttle: vLLM benchmarking CLI

KushagraKanaujia/throttle ↗PyPI: throttle-pro ↗
WHAT IT IS

Measures what a vLLM config change costs in dollars per million tokens, with a 95% confidence interval that says whether the change actually helped.

RESULT STOREMERGEDPR #35 ↗

A persistent, append-only NDJSON store so benchmark runs accumulate instead of re-spending GPU time on known answers. It matches runs on model and revision, GPU, backend and version, changed parameter, and workload shape, and fails closed on identity fields. On a near match it names exactly what differs instead of treating a different GPU or backend version as the same config. Provenance (operator, environment, owned or rented hardware) is mandatory on every record, and a real historical run was backfilled as the first record. 21 new tests.

SERVER_NAME FIELDMERGEDPR #29 ↗

Added a structured server_name field alongside server_version. The manifest recorded the engine's version but never its identity, so which engine a run targeted was only inferable from context.

ROOT-SKIP TEST FIXMERGEDPR #34 ↗

Skips an unwritable-directory test when running as root instead of failing.

README CORRECTIONMERGEDPR #23 ↗

Brought the semantic-cache section up to date with what shipped.

CONFIG VALIDATIONOPENPR #24 ↗

Traced CLI crashes to argparse only re-validating string defaults, so YAML-native ints, floats, and lists bypassed type, range, and shape checks. Fixed at the source in config.py instead of patching each command, including exact-length nargs validation.
